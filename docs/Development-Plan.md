# AI Software Development Agent — Development Plan（项目开发计划）

## 1. 项目概述

**项目名称：** AI Software Development Agent（AI 软件开发智能体）

**项目定位：** AI Agent 工程开发路线的第 4 个综合项目

**计划周期：** 10 天，可根据实际学习和开发情况适当延长

**开发方式：** 手动编码、循序渐进、重视原理与工程实践

**最终目标：** 构建一个能够理解 Python 代码仓库、规划开发任务、修改代码、执行测试、修复错误并输出可审查结果的 AI 软件开发智能体。

项目不仅要求功能可以运行，还要具有完整的工程结构、自动化测试、安全边界和技术文档，最终可以用于 GitHub 展示、简历和技术面试。

## 2. 十天开发计划总览

| Day | 主题 | 核心开发内容 | 最终产物与验收 |
|---|---|---|---|
| **01** | Project Setup & Architecture（项目初始化与架构） | 项目初始化、`src/` 布局、CLI、pytest、Ruff、Git | 可安装、可运行、可测试的 Python 项目骨架 |
| **02** | Repository Explorer（代码仓库探索） | 目录扫描、文件读取、代码搜索、路径边界与文件过滤 | 能探索真实 Python 仓库，正确处理非法路径 |
| **03** | Task Planning（开发任务规划） | 模型 API 接入、任务分析、相关代码上下文收集、结构化计划 | 根据自然语言需求生成可检查的开发计划 |
| **04** | Code Editing & Diff（代码修改与差异） | 受限文件编辑、修改前校验、Git Diff、修改结果检查 | 能安全修改指定代码并展示修改差异 |
| **05** | Test Runner & Verification（测试执行与验证） | 受控执行 pytest / Ruff、退出码、日志、超时、异常处理 | 能自动验证代码并生成结构化测试结果 |
| **06** | Software Development Agent Loop（开发智能体循环） | 整合仓库探索、任务规划、代码修改与测试工具 | 完成第一次端到端的真实 Bug 修复 |
| **07** | Error Recovery & State（错误恢复与状态管理） | 测试失败分析、执行状态、自动重试、失败终止机制 | 能根据失败结果有限重试并安全停止 |
| **08** | Human Approval & Safety（人工审批与安全控制） | 完善操作权限、命令限制、人工审批、审计日志 | 能拒绝越权操作，支持人工审查修改 |
| **09** | Evaluation & Regression Testing（评估与回归测试） | Bug 修复、功能开发、异常处理、安全场景评估 | 可复现的评估集及能力测试报告 |
| **10** | Release & Portfolio（发布与求职展示） | 完善 README、架构文档、CI、使用演示、面试材料 | 完整 GitHub 项目及可复现的求职演示 |

### 阶段划分

- **Day 01–05：工程基础与工具开发。** 建立可靠的代码读取、修改和测试能力。
- **Day 06–08：Agent 核心工作流。** 实现自主开发循环、错误恢复和人工审批。
- **Day 09–10：验证与项目交付。** 证明实际能力，形成完整的求职展示作品。

## 3. 技术方案

| 技术 | 主要用途 |
|---|---|
| Python | 主要开发语言 |
| CLI / argparse | 命令行交互与任务输入 |
| Pydantic | 结构化数据与参数校验 |
| pathlib | 文件和路径处理 |
| subprocess | 受控执行外部命令 |
| Git | 代码差异、变更检查和版本管理 |
| pytest | 自动化测试 |
| Ruff | Lint（代码质量检查）和 Format（代码格式检查） |
| 大模型 API | 开发任务理解、规划和代码生成 |
| Agent Workflow | 开发流程编排、状态管理和错误恢复 |
| GitHub Actions | CI（持续集成）及多版本兼容性验证 |

技术选型原则：

1. 优先复用前三个 Agent 项目已经学习的能力。
2. 大模型优先使用已经能够正常调用的服务，控制成本。
3. 第一版采用 CLI，不增加不必要的前端开发。
4. 优先支持中小型 Python 仓库，不追求所有语言和复杂多智能体架构。
5. 从实现文件工具开始就考虑基本安全限制，Day 08 集中完善安全机制。

## 4. 每日固定开发规范

开发顺序：

**明确目标 → 检查环境 → 编写代码 → 功能测试 → 理解原理 → 完成学习文档 → 最终检查 → 人工验收 → Git 提交**

基本要求：

1. 每天只推进一个明确的工程阶段。
2. Python 文件优先先给完整最终代码，再解释关键实现和设计原因。
3. 新术语首次出现时提供中文解释。
4. 测试优先使用 `tests/` 下的 pytest。
5. 每天完成后执行完整 pytest、Ruff Lint 和 Ruff Format 检查。
6. 学习文档统一放在 `docs/DayXX-*.md`。
7. Debug 只记录真实发生的问题和实际排查过程。
8. 每天提供独立的功能验收步骤，验收后再 Git 提交。
9. 不使用 Codex 代替手动开发。
10. 遇到复杂问题可以延长学习时间，不为了赶进度跳过重要知识。

## 5. 最终项目验收标准

### 5.1 功能能力

- [ ] 能读取和搜索指定 Python 代码仓库。
- [ ] 能理解开发需求并生成结构化计划。
- [ ] 能在授权范围内修改代码并查看 Diff。
- [ ] 能执行 pytest / Ruff 并解析结果。
- [ ] 能根据测试失败信息进行有限自动修复。
- [ ] 能限制危险操作并支持人工审批。
- [ ] 能输出完整、可审查的开发任务报告。

### 5.2 工程质量

- [ ] 项目模块清晰，核心代码易于理解。
- [ ] 具有充分的自动化测试和异常处理。
- [ ] 具备可重复执行的真实开发任务评估。
- [ ] README、安装说明、架构文档和使用示例完整。
- [ ] GitHub Actions 能够执行核心自动化检查。
- [ ] 能够独立演示并解释关键实现、技术选型和工程取舍。

### 5.3 求职成果

最终形成：

- 一个完整的 GitHub 开源展示项目。
- 一套可运行、可复现的软件开发 Agent 演示。
- 一份项目架构及技术总结。
- 一套简历项目描述与面试讲解材料。

## 6. 项目完成原则

**不以完成 10 天任务为唯一目标，而以真正掌握 AI Agent 工程开发能力为目标。**

10 天是基础开发路线，可以根据实际情况延长，但不随意增加偏离项目目标的复杂功能。

项目成功的标准是：**能够在明确的安全边界内，完成真实的软件开发任务，并通过测试与评估证明结果可靠。**
